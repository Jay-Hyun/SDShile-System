# 음악 · 사운드 — 「AI에게 물었다」

## 출처
- 곡: **"Breaking News Background Music (short 4)"** — grand_project, Pixabay **ID 505611** (사용자 제공 파일 `grandproject-breaking-news-background-music_short-4-505611.mp3`)
- 프로젝트 사본: `assets/music/source.mp3` (36.57 s, 44.1 kHz, 원본 −12.8 LUFS, 피크 +0.1 dBFS)
- **라이선스 확인은 사용자 몫이다.** Pixabay Content License 조건(광고 사용 범위 포함)을 집행 전에 확인할 것.
- 합성 음악은 쓰지 않았다. 음악은 위 원곡을 잘라 붙인 것뿐이다. **무음·페이드·로우패스·테이프 스톱·덕킹·피치 변화는 쓰지 않는다**(02 §7-2 "음악은 끊지 않는다"). 마지막 엔딩 페이드만 있다.

## 분석 (`tools/analyze_beats.py` → `beats/source.json`)
- 125.03 BPM, 1비트 P = 0.47988 s (30fps 14.40프레임), 4/4. 첫 다운비트 1.007 s, 이후 다운비트 = 1.007 + 4P·k.
- 구조: 0.5–1.0 인트로 스웰 → 1.007 A섹션(반복 뉴스 비트) → 12.5–16.3 한 단계 가벼운 마디 → **16.363 B섹션 진입 크래시**(고역 심벌 추가) → 29.8 빌드 → **31.719 마지막 크래시** → 33.6–36.5 꼬리.
- 원곡에 브레이크(정적)는 없다. "고민 중…" 개그도 이제 음악이 흐르는 채로, 화면 글자만으로 연출한다. (이전 판의 테이프 스톱 → 클린 스톱(80ms 페이드 + 무음)은 모두 클라이언트 피드백("먹먹하다", "고민 중에도 브금 끊지 마")으로 뺐다.)
- 대체 곡(A, kornev)은 쓰지 않았다. B로 30초·15초 모두 다운비트 진입·크래시 착지가 맞아서 바꿀 이유가 없었다.

## 편집 (`tools/make_audio.py` ← `lib/cue.js`, 결과 `beats/cuts-30.json`, `cuts-15.json`)
첫 구간을 **정수 박자 R**(30s 박자 30 = 14.397 s, 15s 박자 14 = 6.718 s)까지 이어 재생하고, R 에서 두 번째 구간의 **다운비트 시작**으로 6 ms 등전력 크로스페이드로 잇는다(반 마디 짧은 마디). R 이 정수 박자라 박 그리드가 A·B·C 에서 하나로 이어진다. 두 번째 구간 안은 그대로라 원곡 크래시(16.363)가 R + 2마디(30s) / R + 1마디(15s)에 온다.
| 판 | 영상 구간 | 원곡 구간 | 역할 |
|---|---|---|---|
| 30s | 0.000–14.397 | 1.007–15.404 | A. C1–C5. 고민 중… 구간(11.98–14.40)에도 계속 흐른다 |
| 30s | 14.397–25.914 | 12.524–24.041 | B. **R = B 의 다운비트 = 🙂 답이 줄 상승으로 등장**. 18.236 = 원곡 16.363 크래시 = **[상담사 연결]이 열리는 1200ms 의 중간점** |
| 30s | 25.914–30.000 | 29.800–33.886 | C. 다운비트 이음 = **엔드 시퀀스의 슬로건 교체**. 27.833 = 원곡 31.719 마지막 크래시. 29.65–30.0 엔딩 페이드 0.35 s |
| 15s | 0.000–6.718 | 1.007–7.725 | A. C1–C3. 고민 중… 구간(4.9–6.72)에도 흐른다 |
| 15s | 6.718–10.557 | 14.443–18.283 | B. R = 🙂 답. 8.638 = 원곡 16.363 크래시 = 오프닝 윈도우 중간점 |
| 15s | 10.557–15.000 | 29.800–34.243 | C. 12.477 = 원곡 31.719 마지막 크래시 = **C6 하드컷(슬로건)**. 14.6–15.0 엔딩 페이드 0.4 s |

이음새는 모두 겹치는 등전력 크로스페이드(6 ms)다. 이전 판은 앞 조각 끝 6 ms 페이드아웃과 뒤 조각 첫 6 ms 페이드인이 겹치지 않아 이음새마다 약 12 ms 의 홈이 있었다.

## 효과음 (2개뿐)
"조잡한 효과음은 줄여 달라"는 피드백으로 합성 효과음(팝·휙·스윕·차임·귀뚜라미·초침·타건·마커)은 모두 뺐다. 남은 것은 부드러운 탭 두 번이다. 고민 중… 구간은 순수하게 음악만 흐른다.
| 판 | 시각 | 효과음 | 레벨 |
|---|---|---|---|
| 30s | 11.898 | 질문 전송 탭 | 주변 음악 RMS(±0.5s, -14.0 dBFS) − 20 dB |
| 30s | 17.213 | [상담사 연결] 누름 탭 | 주변 음악 RMS(±0.5s, -15.4 dBFS) − 20 dB |
| 15s | 4.900 | 질문 전송 탭 | 주변 음악 RMS(±0.5s, -13.1 dBFS) − 20 dB |
| 15s | 7.613 | [상담사 연결] 누름 탭 | 주변 음악 RMS(±0.5s, -15.4 dBFS) − 20 dB |
탭 = 170 Hz 몸통(14ms 감쇠) + 2.5 kHz 아래로 깎은 짧은 클릭. 화면 동작보다 1프레임 늦게. 목록은 `beats/cuts-*.json` 의 `sfx`.

## 점검 (`python3 tools/audio_check.py 30|15 [파일]`, MP4 오디오도 된다)
1. 10 ms RMS 가 −40 dBFS 미만으로 이어지는 가장 긴 구간(엔딩 페이드 제외) — 50 ms 이상이면 끊김.
2. 고민 중… 구간 RMS 와 앞뒤 2초 평균의 차 — ±6 dB 이내.
3. 이음새 ±3 ms 의 최대 샘플 간 차이 ÷ 주변 ±300 ms 의 99.9 백분위 — 클릭이면 ≫ 1.
4. 10 kHz 이상 비율을 같은 구간 원곡과 비교 — ±1 dB 이내(효과음이 든 구간은 뺀다).

## 마스터
- 두 스템(`assets/audio/bgm*.wav`, `sfx*.wav`)에 같은 게인과 같은 룩어헤드 리미터(샘플 피크 −1.7 dBFS)를 건다.
- 믹스 실측(ffmpeg ebur128, `beats/cuts-*.json`): **30s -15.0 LUFS / TP -2.2 dBTP**, **15s -15.0 LUFS / TP -3.1 dBTP** (리미터 작동 0.0 / 0.0 dB). 들어보지는 못했다(측정값만).
- 다시 만들기: `npm run beats && npm run audio`.
